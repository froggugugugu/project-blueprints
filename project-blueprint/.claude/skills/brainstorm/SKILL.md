# `/brainstorm` — `/prd` 前段の Socratic ブレスト

## いつ使うか

`/prd` を実行する前に、要求メモの**前提と曖昧さを構造化**したいときに使う。
「とりあえず PRD を書く」前のワンクッションで、後の手戻りを大幅に減らす。

## 入力

- **要求メモのファイルパス**(`input/requirements/foo.md` 等)
- または **整理したいトピックの一文**(例: 「サブスク機能を追加したい」)

## 出力

`output/brainstorm/BRAINSTORM_<topic>_<date>.md` に以下の構造で保存:

```markdown
## 1. 要求の核(一文)
## 2. 前提の棚卸し(明示・暗黙の両方)
## 3. ステークホルダーと利害(誰が何を期待し、何を恐れるか)
## 4. やる/やらない境界の候補(3 案以上)
## 5. 未解決の質問リスト(優先度付き)
## 6. 次のステップ(`/prd` を実行できる状態になっているか?)
```

## ワークフロー

1. **入力読込** — メモを読む。または対話で1〜2文の起点を聞く
2. **Socratic 質問の連射**(AskUserQuestion で 1〜4 個ずつ、最大 3 ラウンド)
   - 「誰のための機能か?」「成功の定義は?」「なぜ今なのか?」
   - 「やらない選択肢はあるか?」「失敗したらどう撤退するか?」
3. **暗黙の前提を顕在化** — 「【前提】」マーカーで明示
4. **やる/やらない境界の 3 案提示** — Minimum / Standard / Ambitious
5. **未解決質問のリスト化** — `/prd` 起動前に解消すべきものに ★ を付与
6. **保存** — `output/brainstorm/` に書き出し、ユーザーに提示

## 制約

- **コード・テスト・本番ドキュメント変更禁止**(`docs/`, `src/`, `tests/` 不可)
- **推測で機能を膨らませない** — 入力にない要件を勝手に追加しない
- **出力先は `output/brainstorm/` のみ** — 他ディレクトリへの Write は不可
- **質問は 1 ラウンド最大 4 個** — 過剰な質問でユーザーを疲弊させない
- **3 ラウンド以上は禁止** — それ以上は `/prd` に進む合図

## 関連スキル

- 整理が完了したら `/prd <出力ファイル>` で正式 PRD へ
- 大きな設計判断が出たら `/adr <タイトル>` で並行記録
- 設計段階の脅威モデルが必要なら `planner` agent + `security-reviewer` の組み合わせ

## 想定される質問例(Socratic テンプレート)

| カテゴリ | 質問例 |
| -------- | ------ |
| 動機 | なぜ今これをやるのか? 1 ヶ月後でも同じ価値があるか? |
| ユーザー | 主たるユーザーペルソナは? ニッチケースは誰か? |
| 成功条件 | リリース後どうなれば成功? 計測指標は? |
| やらない | 意図的にやらないことは何か? なぜか? |
| 撤退条件 | 失敗が判明したらどう戻すか? データは? |
| 制約 | 法務・セキュリティ・SLA で外せない制約は? |
| 代替案 | 同じ価値を別の方法で実現できないか? |

## ゲート

- **ゲート 1**: ブレスト完了時に「`/prd` に進める状態か?」をユーザーに問う
- **ゲート 2**: 未解決質問が 3 件以上残っている場合は `/prd` への遷移を保留する
