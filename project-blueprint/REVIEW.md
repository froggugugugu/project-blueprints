# レビュー指示(Claude の Code Review 用)

Claude の Code Review(GitHub App)がこのリポジトリの PR を審査するときの基準。`CLAUDE.md` は全作業の共通文脈で、
このファイルはレビュー専用。ローカルの `/code-review` と CI の `claude -p '/code-review'` はこのファイルを読まないので、
両方に効かせたい規則は `.claude/skills/code-review/SKILL.md` に置く。長くすると効きが薄れるため、レビューの挙動を変える規則だけを書く。

## Important の定義

Important(🔴)は次に限る: 動作を壊す論理誤り / データ漏えい(ログ・エラーへの PII やシークレット)/
ロールバックできない移行 / テナント境界を越えるクエリ / 受け入れ基準の未達。
命名・整形・リファクタ提案は Nit(🟡)まで。本テンプレートの `/code-review` の MUST に相当する。

## Nit の上限

1 レビューで Nit は 5 件まで。超えた分は要約に「他 N 件」と数だけ書く。Important が無ければ要約の先頭に「ブロッカーなし」と書く。

## 報告しないもの

- CI が既に落とすもの: lint・整形・型エラー
- 生成物・ロックファイル・ベンダリングされた依存(`dist/`、`*.lock`、`vendor/`)
- AI が生成する領域: `output/`、`testreport/`、`docs/`(内容の正しさは実装レビューで見る)
- テスト専用コードが意図的に本番規則を破っている箇所

## 常に確認するもの

- 新しい API ルート / コマンドには統合テストがある
- ログ・エラーメッセージにメールアドレス・ユーザー ID・リクエスト本文を含めない
- `docs/` と `project-config.md` §2 / §3 の更新が実装変更に追随している(`AGENTS.md` のドキュメント管理)
- `--no-verify`・`--force` の使用や、`.env` / 秘密鍵のコミットが無い
- レイヤー間の依存方向(`project-config.md` §4.4)に違反していない

## 根拠の基準

振る舞いに関する指摘は `file:line` で根拠を示す。名前からの推測は Nit 止まりにする。

## 再レビューの収束

同じ PR の 2 回目以降は新しい Nit を出さず、Important だけを報告する。

## 要約の形

先頭 1 行に「Important N / Nit M」を書き、Important が無ければ「ブロッカーなし」で始める。
