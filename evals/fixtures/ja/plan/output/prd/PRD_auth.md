# PRD: ユーザー認証(ログイン / ログアウト)

## 1. 概要

- **背景**: 備品の貸出記録に「誰が借りたか」を残すため、社員がログインして操作する必要がある
- **スコープ内**: メールアドレス + パスワードによるログイン、ログアウト、ログイン状態の保持(ブラウザを閉じるまで)
- **スコープ外**: SSO / OAuth、パスワードリセット、多要素認証、管理者による強制ログアウト

## 2. 用語

| 用語 | 定義 |
| --- | --- |
| セッション | ログイン後、ブラウザを閉じるまで維持される認証状態 |
| ロック | 連続失敗後に一定時間ログインを拒否する状態 |

## 3. 機能要件

| ID | 要件 | 受け入れ基準 |
| --- | --- | --- |
| FR-001 | メールアドレスとパスワードでログインできる | 正しい組み合わせで `/` に遷移し、ヘッダーに表示名が出る |
| FR-002 | 誤った資格情報ではログインできない | 「メールアドレスまたはパスワードが違います」を表示し、どちらが誤りかは明かさない |
| FR-003 | 5 回連続で失敗すると 15 分ロックされる | 6 回目は正しい資格情報でも拒否され、ロック解除時刻を表示する |
| FR-004 | ログアウトできる | ヘッダーの「ログアウト」でセッションを破棄し `/login` に遷移する |
| FR-005 | 未ログインで保護ページにアクセスすると `/login` に遷移する | 元の URL をクエリに保持し、ログイン後に戻る |

## 4. 非機能要件

| ID | 要件 |
| --- | --- |
| NFR-001 | パスワードは平文で保存・ログ出力しない(bcrypt 等でハッシュ化) |
| NFR-002 | ログイン API の応答は p95 で 500ms 以内 |
| NFR-003 | 入力は Zod で検証し、エラーは画面上の該当フィールドに表示する |

## 5. データモデル

- `User { id, email, displayName, passwordHash, failedAttempts, lockedUntil }`
- `Session { id, userId, createdAt, expiresAt }`

## 6. 受け入れ基準(全体)

- FR-001〜FR-005 のユニットテストがあり、ログインフローの E2E テスト(正常系・失敗系・ロック)が通る
