# Constitution — Inviolable Principles

This file defines the **7 immutable principles** of the `project-blueprints`
repository. It sits above `project-config.md` (variable parameters); when AI
attempts to violate them, `scan-harness.sh` flags it.

> Changes require an explicit PR with discussion, and the
> `.claude/.constitution.sha256` must be updated in the same PR.
> AI is prohibited from rewriting this file unilaterally.

---

## 1. Don't blur the human / AI responsibility split

`project-config.md` is decided by humans. `docs/`, `output/`, `testreport/`
are generated by AI. Don't let this boundary erode.

- **Human-managed**: `project-config.md`, `input/requirements/`, `constitution.md` (this file)
- **AI-managed**: `docs/` (project-derived info), `output/` (deliverables), `testreport/` (raw tool data)

## 2. Maintain the JA / EN bilingual mirror

`project-blueprint/` (Japanese) and `project-blueprint-en/` (English) must stay
structurally synchronized. A change to one must be reflected in the other.
Wording may be translated; structure (sections, files, features) must remain identical.

## 3. Don't reduce the 5 quality gates

PRD complete / Design complete / Task decomposition complete /
Implementation complete / Verification complete — these 5 points must remain
as human intervention opportunities. Human intervention is optional, but the
gates themselves must not be removed.

## 4. Maintain the three-layer separation (skill / team / agent)

- **Skill**: a procedure for one phase (`.claude/skills/`)
- **Team**: orchestration combining multiple skills (`.claude/teams/`)
- **Agent**: single-shot specialist delegation (`.claude/agents/`)

Don't mix layers. A skill calling a team, an agent spawning agents in a loop,
etc. are prohibited.

## 5. Don't weaken the 3-layer defense

Layer 1: hooks (always-on) / Layer 2: deny rules (shared) / Layer 3: allow rules (personal).
Layer 1 stays active even with `--dangerously-skip-permissions`. Changes that
disable or stop hooks are prohibited. Adding new hooks is permitted.

## 6. Keep CLAUDE.md within 200 lines (target)

Bloat reduces compliance because important rules get buried (pitfalls.md #1, #18).
Detailed rules go to `.claude/rules/`, `.claude/skills/<name>/SKILL.md`, or `docs/`.

## 7. Never commit secrets

`.env*`, private keys, and API tokens are protected by `protect-files.sh`.
`scan-harness.sh` also detects secrets that might leak into the harness itself.
If a leak is detected, immediately purge the history and rotate the key.

---

## Change protocol

1. Create a PR proposing changes to this file
2. Reach consensus in review
3. After merge, update the hash:

   ```bash
   sha256sum constitution.md | cut -d' ' -f1 > .claude/.constitution.sha256
   ```

4. Include `.claude/.constitution.sha256` in the same PR (no follow-up PR)

`scan-harness.sh` blocks skill invocation under the `strict` profile when it
detects a hash mismatch (warns only under `standard`).
